# The Notion workspace template

Every discovery gets the same Notion page, built by `setup` (step 5) from this file. It is a dashboard of the shared Discovery tracking databases, filtered on the project, plus three mirror pages. Same layout for every project, so anyone at Hexa reads any discovery the same way.

Built with the Notion tools only: `notion-create-pages` for the page and its children, `notion-create-view` with `parent_page_id` for each linked view (appended at the end of the page, in the order below). The guard allows a linked view only on a page of our workspace and only with `FILTER "Project" = "<Project>"` first. Never create a view tab on a shared database itself (`database_id`): that changes the studio's shared database.

## 1. The page

Parent: `project.json` `notion.project_page`. Title: `🧭 <Project> discovery`. Icon: the project's emoji in WTF Projects, else 🧭. `allow_async: false`. Content (English):

```markdown
<callout icon="🧭">This page is generated by the Hexa discovery harness. Owner: <user mention>. Sprint: <start> → draft proposal <date> → go / no-go <date>. Everything below is filtered on Project = <Project>; edit the rows, not the views.</callout>
**Idea in force (<version>, <date>):** <the idea in one sentence>
**This week:** <Our read of the latest Weekly reviews row>
```

`review` rewrites the two bold lines every week (`notion-update-page`).

## 2. The linked views, in this order

`data_source_id` values are in `docs/notion.md`. Every `configure` starts with `FILTER "Project" = "<Project>"`.

| # | Name | Data source | Type | configure (after the Project filter) |
| --- | --- | --- | --- | --- |
| 1 | 📈 Weekly reviews | Weekly reviews | table | `SORT BY "Week of" DESC; SHOW "Review", "Week of", "Our read", "Design partners ready to pay", "Founder search", "Next week we test"` |
| 2 | 📊 Funnel | Contacts | chart | `GROUP BY "Stage"; CHART column AGGREGATE count COLOR blue` |
| 3 | 👥 Pipeline | Contacts | board | `GROUP BY "Stage"; SHOW "Company", "Role", "Priority", "Next action date"; CARD LAYOUT compact` |
| 4 | 📅 Next actions | Contacts | table | `FILTER "Next action date" <= "today"; FILTER "Stage" != "Not for us"; SORT BY "Next action date" ASC; SHOW "Name", "Company", "Stage", "Next action", "Next action date", "Channel", "LinkedIn"` |
| 5 | 🎙️ Calls | Contacts | table | `FILTER "Stage" = "Call done"; SORT BY "Call date" DESC; SHOW "Name", "Company", "Type", "A-player", "Call date", "Key learning", "Granola transcript"` |
| 6 | ⭐ A-players | Contacts | table | `FILTER "A-player" = TRUE; SORT BY "Call date" DESC; SHOW "Name", "Company", "Role", "Why A-player", "Call date"` |
| 7 | 🧪 Hypotheses | Hypotheses | board | `GROUP BY "Status"; SORT BY "Code" ASC; SHOW "Code", "Next week", "Updated"` |
| 8 | 🔥 Problems | Problems | table | `SORT BY "Code" ASC; SHOW "Problem", "Code", "Status", "Who has it", "Proof"` |
| 9 | 💡 Idea log | Idea log | table | `SORT BY "Date" DESC; SHOW "Idea", "Version", "Status", "Date", "What changed"` |

`show_data_source_title: false` (the view name is the section title).

## 3. The mirror pages

Created after the views, as children of the workspace page (they appear at the bottom), and stored in `project.json` `notion.pages`:

| Page | Key | Mirror of | Updated by |
| --- | --- | --- | --- |
| 📄 Current idea | `current_idea` | `1-idea/current.md` | `review` (and `setup`) when the idea changes |
| 📚 What we've learnt | `learnings` | `3-knowledge/README.md` | `review` |
| 🎯 IDEA Framework | `idea_framework` | `1-idea/idea-framework.md` | `review` near the sprint deadlines |

Mirrors are written in English; repo files are cited as text, only external URLs are links.

## 4. Repair (idempotent)

`setup` fetches the workspace page first. Views are recognised by their name: create only the missing ones, in the table order. If a view was edited by hand, leave it. If the page was deleted, rebuild it and update `project.json`.

## Changing the template

Edit this file in the template repo (`orpheo28/hexa-discovery`). Existing projects get it with `npm run update-harness`, then "setup" adds the missing views. Any property name used here must exist in the shared databases (`docs/notion.md`); the board's schema contract wins.
